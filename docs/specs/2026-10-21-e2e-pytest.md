# swaywardlock: end-to-end tests in pytest

Status: implemented 2026-10-21 (six area ports and two reviewed integration batches). Parent spec: `2026-10-19-swaywardlock.md` (Testing).

## Problem

`contrib/e2e-sway` is one bash script of about 3,200 lines: 61 tests, about 100 helpers, a
dozen inline `python3 -c` snippets and one `ppm-pixel` process per pixel read. Almost every
merge conflicts in it (the single default `TESTS=` line always does, and a hand resolution once
dropped a closing brace between two tests). The recurring test bugs are bash ones: zombies
counted as alive, a first frame sampled before it is on screen, `set -u` aborts, a missing exit
status check, checks that pass for the wrong reason. Tests run one after another, each with its
own headless sway; CI time grew from 8 to 10 minutes in a day.

## Approach

A pytest suite under `tests/e2e/`, run next to `contrib/e2e-sway` while tests move over one area
at a time; the bash script is deleted when it is empty.

- **Discovery, not a list.** One test per function in per-area files (`test_password.py`,
  `test_labels.py`, `test_ring.py`, ...). No central `TESTS=` line, so adding a test never
  conflicts with another branch adding one.
- **One session fixture.** `lock_env` starts a headless sway in a fresh temporary runtime dir
  (the same environment `start_sway` sets up today: headless backend, pixman, no libinput, 320x240
  unless a test asks otherwise, `XDG_CONFIG_HOME` isolated), yields a handle, and always stops
  sway, kills every process the test started and removes the dir, also on failure and timeout.
  Teardown holds Ctrl-C, SIGTERM, SIGHUP and the timeout alarm until it is done (by swapping
  their handlers, which holds process wide, also in an xdist worker with its execnet thread).
  Each dir has a reaper process that cleans it up if the pytest process is SIGKILLed (a death
  signal cannot do it: sway has file capabilities, and their exec clears it).
  Logs are kept under `--keep-logs DIR` and printed on failure.
- **Helpers in Python.** A `Locker` handle (start with a config string, wait for `session
  locked`, type with wtype, send signals, wait for exit with a status); screenshots from one grim
  run each, parsed in process; `pixel`, `matching` and `colour_width` as functions over a
  screenshot; `alive()` that treats zombies as gone; contrib tools (vkbd, vptr, fake-fprintd,
  forge-fprint, wl-inject-finished, wl-drop-key-release, clock-jump) wrapped as fixtures.
  Helpers own their waiting: `poll(cond, timeout)` replaces fixed sleeps, and every screen read
  on the test's environment polls until two samples in a row agree and meet the check:
  `expect_colour(name, want, x, y)`, `expect_width(name, colour, box, until)` (bash
  `settled_width`) and `expect(name, read, until)` for any other function of a screenshot. The
  one single sample is `snapshot()`, for a value that must not change after a sleep.
- **Readable failures.** The `expect*` reads report the point or box, the expected value, the
  last seen one and the distinct values before it, and how long they waited.
- **Parallel.** pytest-xdist runs tests at once (`-n auto` locally, `-n 4` in CI); each test has
  its own sway, so the only shared state is fixed paths or bus names, which are made per test.
  A per-test timeout (pytest-timeout, or a fixture timer) kills a stuck test.
- **Test-only dependencies.** `python3-pytest`, `python3-pytest-xdist` and `python3-pytest-timeout`
  in the dev container and CI only; the packages and the converters stay stdlib only.

## Migration and parity

1. Scaffolding: `tests/e2e/conftest.py` and `tests/e2e/lib/`, the fixtures and helpers above,
   and two areas ported to prove it (`password`, `defaults`). `contrib/gate` and CI run the pytest
   suite after the bash one. New tests go to pytest from this point on.
2. Each further area moves in its own change: its bash functions are deleted, the pytest file
   added, and the change shows parity: every check name kept (as the assertion message), and for
   each test a mutant or a disabled feature that made the bash check fail now makes the pytest one
   fail (the audit's mutation and refuter harnesses are reused for this).
3. When `contrib/e2e-sway` is empty it is deleted with its `TESTS=` line and the union helper.

Large areas (labels, widgets, ring, rotate, vibrancy, reload, shadows) move after the Phase 3
units that edit them have landed, so nothing is ported twice.

## Not in scope

Unit tests (they stay in Rust), the converter tests (already Python, stdlib unittest), changing
what is tested.

## Done when

`contrib/e2e-sway` is gone; `contrib/gate` and CI run `pytest tests/e2e -n auto` (CI `-n 4`);
every former check exists by name; a full run is faster than the serial bash run on the same
machine; a test killed by its timeout, a second signal during teardown or a SIGKILL of pytest
leaves no sway, locker or temporary dir behind.
