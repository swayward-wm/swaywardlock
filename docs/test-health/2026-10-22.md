# Test-health report — 2026-10-22

## Scope and outcome

Retrospective report for the 2026-10-21–22 gate pilot, readiness-wait upkeep and
bash-to-pytest migration. Written after the workstreams closed, from retained
execution logs, commits and review records; **not a fresh benchmark run**.
Future passes should read this report first, then re-measure. Leave this file
unchanged and write a new dated report for each subsequent pass.

The gate now has `--fast` and `--slow` modes; its default runs both. All 64
legacy bash cases moved to six pytest area files, with independent parity and
retirement reviews. The final suite has 259 passing Rust tests and 100 passing
pytest tests. The ordinary ignored installed-PAM unit is exercised separately
by `contrib/test-real-pam`. Eight release-marker scans remain required.

Two comparable readiness changes improved their specific cases without
removing assertions. Warm local full-gate cost fell substantially after
parallel pytest migration, but the inventories and caches changed: the table
below is **not a controlled whole-suite speedup claim**.

The final CI slow step sum was **284.607 s**, under the 300 s target on that
runner. Its release build took 192.643 s. This is one successful CI observation,
not proof that every cold machine or future run stays within budget.

### Comparable area changes

- **Vibrancy readiness (`36273ff`):** remove 0.3 s padding only from four callers
  already polling pixels. Retain padding for the two single-shot noise/orientation
  captures. Six targeted runs preserved all seven assertions; mean case time
  **3.350 → 2.140 s** (36.1% faster). These measurements were supplied with the
  reviewed pilot, not reconstructed from a later full gate.
- **Text-shadow readiness (`226f2e2`, merged as `d89bef9`):** three positive waits
  became bounded polls. Same private debug binary/environment: before **10.585 s**;
  after **8.634 / 8.633 / 8.605 s**, mean **8.624 s** (18.5% faster), **19 assertions**
  each, no failures/skips. The final width/red-pixel predicates reject stale frames;
  the subsequent full one-second negative cache window remains.
- **Build reuse, measured separately:** identical private-target release build
  plus three scans: cold **85.407 s**, warm **0.255 s**, both exit 0. Existing Cargo
  reuse already works; no compiler-cache service or shared writable target was added.
- **Migration evidence:** I1 removed exactly 49 bash functions/tokens and retained
  15 test bodies plus 43 helpers unchanged. I2 replaced those last 15. The union
  remains 64 disjoint case mappings. Every area had independent source/parity review,
  including negative controls; controls failing at a first assertion were not
  counted as proof of every later variant.

## Findings, decisions and rejected verdicts

This section covers test-health and harness findings in this pass, not every
production issue discovered by the separate multi-round locker audit.

| Finding or proposal | Evidence / decision |
|---|---|
| Slow gate exceeds five minutes | Initial slow 341.696 s; later pilot 345.041 s. Queue upkeep, preserve checks. Budget was a scheduling trigger, not a permission to omit auth or scans. |
| Broader five-wait text-shadow speedup | Fresh refuter narrowed it to **three positive waits**. Changed-frame polls must require width **and** red-count growth; relayout requires visible red and increased text x-origin. Other waits, especially reload no-change/crossfade and the full one-second cache window, were **KEEP**. |
| Delete/merge tests to reduce time | No behavioral MERGE, DELETE or MOVE-DOWN was adopted. The top 20 cases were kept. Bash deletion occurred only after named pytest replacement and accepted parity, not as coverage reduction. |
| Add compiler-cache/build-reuse abstraction | Not warranted: private cold/warm build measurement demonstrated existing Cargo reuse. Shared writable targets would add isolation risk. |
| Migration plan allowed stale logs | **Rejected.** `spawn` appends and default `lock.log` could let a previous invocation's marker satisfy a later wait. Require unique logs per invocation and matching handles; narrow re-review accepted, all area reviews inspected/probed this. |
| Scaffold only polls `expect_colour` | **Rejected.** Other public reads encouraged first-frame flakes. Public expectations gained bounded settled polling; explicit snapshots remain for temporal/negative sampling. |
| Thread-only signal masking during cleanup | **Rejected.** An xdist IO thread could receive a signal and interrupt teardown. Process-level signal handling was corrected; parallel interruption tests supplied evidence. |
| SIGKILL leaves plain-pytest children | **Rejected.** A per-runtime reaper was added; plain and xdist parent-death checks verify cleanup, rather than relying only on a later stale-dir sweep. |
| Cleanup self-test races disappearing PIDs | **Rejected.** `/proc` reads after a stray-process scan could raise FileNotFoundError. Treat vanished PIDs as gone and poll reap completion. |
| Cleanup SIGINT probe inherits ignored signal | **Rejected.** Background noninteractive shells can ignore SIGINT. Probe children reset signal dispositions; pre-fix run failed after 31.8 s, corrected run passed in 9.5 s; worker reported 30 parallel cleanup runs without failure. |
| I1 deletion regex cut a heredoc early | First local attempt failed `bash -n`; discarded with restore before commit. Corrected boundaries independently verified complete heredocs, 49 removals and unchanged remaining helpers/tests. Invalid attempt never credited as a pass. |
| I2 still names retired harness in live references | **Rejected.** RPM comment, ppm-pixel description and tool-placeholder guidance corrected; ppm-pixel itself retained because tests still use it. |
| Keyboard layout CI flake attributed to fonts | **Refuted by experiments.** Forced cross-client event ordering produced the same failure with a different font. Modifier reset and another keyboard's key needed cumulative command acknowledgments, not wider pixel tolerance or arbitrary sleep. Stale-ack regression now catches an early substring match. |
| Quiet keyboard arrival solved by startup barrier | **Refuted.** Forced late binding still failed after barriers. Initial post-enter modifier snapshots wrongly took speaking precedence; production fix was audited separately. Test prerequisites and negative windows were kept. |
| Refocus test / repeat-removal test meaningful as written | **Refuted.** A missing refocus re-arm survived the suite; repeat-stop checks never established actual repeat. Persisted real leave/enter/snapshot refocus probe and positive repeat-rate, beyond-first-deletion and held-wakeup controls before removal. Both two-second negative windows remain. Intended mutants now fail; no claim that deleting explicit repeat.stop is necessarily killed when another guard independently stops it. |
| Shadow downscale comparison on faint profile | CI's last profile peaked at **1/255**; mass 592 vs 504 differed beyond tolerance while local 620 vs 572 passed. Enlarged only that case to a measurable profile (peak 55), retaining other cases. No blanket tolerance increase. |
| Stronger GPU tolerance needed for wrong pass-count mutant | **Refuted as the lowest-level requirement.** A pure plan test verifies pass decrement/offset progression without Mesa rounding risk; retained rendered approximation remains separate. A later pure policy test also discriminates doubled pixel budget. |
| Conditional modifiers-without-enter behavior | Source-supported pre-existing indicator limitation; runtime reachability on tested sway unverified. Documented optional limitation, no speculative production patch or new broad matrix. |

Area reviews reused equivalent committed-tree evidence and ran uncovered probes
rather than repeating full gates. Some supplied same-family fresh-context checks;
model-family independence and actual executable evidence were stated separately.
Historical Sol security refusals were never counted as completed security checks.

## Remaining bottleneck and next pass

**Cold release compilation dominates slow-gate risk.** Final CI spent 192.643 s
building release versus 88.001 s in pytest and 3.112 s in try-lock. Total slow
steps were 284.607 s: about 15 s of margin. Warm local slow steps were 82.528 s;
these are different conditions, not interchangeable estimates.

Priorities for the next pass:

1. Read this report, then measure current cold and warm gates under controlled
   worker contention. Record actual wall time as well as step sums.
2. Profile current pytest setup/teardown and the slowest 20 cases with
   `--durations=20`. Keep deliberate temporal and negative windows; optimize only
   evidenced readiness padding or duplicated work.
3. Measure safe isolated release build reuse separately. Existing Cargo warm reuse
   is effective; do not introduce shared writable targets or remove scans to meet
   budget. Assess cache/toolchain cost before adding a compiler-cache service.
4. Preserve real-PAM privilege checks, nonzero test selection, all eight release
   scans, per-test process isolation and meaningful repeat/refocus positive controls.
5. Commit another dated report, including any rejected optimization proposals and
   the resulting budget status. No edits to this report.
